# Polar billing for self-hosted installs

## Summary

Self-hosted DiggerAI can sell Pro, Pro+, and Ultra through Polar (sandbox first). Polar checkout and portal replace Stripe when `NEXT_PUBLIC_BILLING_PROVIDER=polar`; paid access reaches the app through WorkOS user metadata and the WorkOS JWT template, so Next.js, Convex, and the browser keep reading the `entitlements` claim.

## Changes

- `lib/billing/polar.ts`, `lib/billing/provider.ts`: Polar client, checkout, portal, subscription status, WorkOS metadata sync, webhook user lookup.
- `app/api/subscribe`, `app/api/entitlements`, `lib/actions/billing-portal.ts`, `lib/actions/subscription-status.ts`: Polar branches; entitlement refresh pulls Polar state first.
- `app/api/polar/webhook/route.ts`, `proxy.ts`: signed webhook that re-syncs the customer.
- `lib/auth/entitlements.ts`, `app/contexts/GlobalState.tsx`: accept the comma-separated claim; a billing provider turns off the self-hosted grant.
- `app/components/AccountTab.tsx`, `PricingDialog.tsx`: plan changes and cancellation open Polar's portal; Team button hidden.
- `app/components/SettingsDialog.tsx`, `SidebarUserNav.tsx`: Extra Usage (Stripe-only) hidden; `GlobalState.tsx` strips Polar's `customer_session_token` from the URL.
- `scripts/polar-setup.ts`, `docs/polar-billing.md`, `.env.local.example`: product creation and setup steps.

## Decisions

- Entitlements live in WorkOS metadata (`billing_entitlements`, manual `granted_entitlements`) instead of a Convex table: one claim already feeds every consumer.
- Polar's portal handles plan changes; no proration preview in-app. Proration set to "Prorate & charge now".
- Products are found by `metadata.plan`, so no product IDs in env.

## Verification

- `npx jest lib/billing/__tests__/polar.test.ts lib/auth/__tests__/entitlements.test.ts`: 16 passed.
- Targeted suites (AccountTab, PricingDialog, billing actions, subscribe, entitlements, contexts): 157/158 passed; the failure is the existing Windows currency-locale test.
- `npx tsc --noEmit`: pass. ESLint and Prettier on changed files: clean.
- Real WorkOS token for a temporary user carried `"entitlements": "pro-plus-plan,pro-plus-monthly-plan"` from metadata.
- Polar sandbox org `diggerai`: `scripts/polar-setup.ts` created 6 products; re-run reported all `ok`.
- End to end on the owner account (manual grant removed during the test): checkout with test card -> `/api/entitlements` returned `pro`; portal plan change to Ultra -> webhook set `ultra-plan`; portal cancel -> Account showed "Cancellation scheduled"; API revoke -> webhook cleared access (`free`). Webhook deliveries returned 200 through a temporary cloudflared tunnel; forged signature -> 403.

## Limitations

- The Polar webhook endpoint points at a stopped temporary tunnel; set a public URL before relying on webhooks.
- Without a public URL, cancellations reach paying users only on their next entitlement refresh.
